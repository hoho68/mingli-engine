# 六爻古籍定向证据补强设计（022）

- **Status**: Approved design baseline
- **Date**: 2026-08-22
- **Branch**: `codex/022-liuyao-classics-targeted-evidence`
- **Base**: 已发布的六爻 V1 主分支提交 `c391ad88d91cbd634e8392026fa705c3cfd6586a`
- **Scope decision**: 只补证据，不新增推理输入，不把应期升级为 `computed`

## 背景与事实基线

用户提供的 1517 页 PDF 目录包含《增删卜易》《卜筮正宗》《卜筮全书》
《易林补遗》《易冒》《易隐》《火珠林》。该文件与 batch_20260714 已登记的
`liuyao_source_batch_20260714_001` 所对应原始文件虽然二进制 SHA-256 不同，
但已经完成内容等价核验：

- 页数均为 1517；
- 全书提取文本均为 1,682,123 字符，文本 SHA-256 均为
  `701FE962C9CC87F7F3E246C299F1FACC0506FBBFFDD35F9353C583ADC00E2DB2`；
- 七部书的起始页（PDF 页 1、292、529、977、1119、1240、1412）渲染结果逐页相同。

因此，新文件是已登记原始内容的重复封装，不构成新来源。原规格中“后续增补
《增删卜易》《卜筮正宗》”是来源识别不充分造成的陈旧表述；正确状态是“已包含，
但重点章节尚未完成定向、系统化的证据提炼”。

当前六爻正式证据共 70 条，分布为：

| rule_family | 条数 |
|---|---:|
| yong_shen_selection | 6 |
| shi_ying_relation | 2 |
| moving_line_dynamics | 5 |
| six_spirits_attachment | 3 |
| month_day_strength | 4 |
| void_break_state | 2 |
| yingqi_timing | 1 |
| category_judgment | 47 |

其中 `yingqi_timing` 只有 1 条现代作者文本证据；`shi_ying_relation` 的 2 条证据中
只有 1 条为通用爻位规则，另 1 条限定在婚姻语境。本阶段优先补强这些证据薄弱处。

## 目标

1. 更正文档中的典籍覆盖事实，明确 source 001 已包含七部古籍，不新增重复来源记录。
2. 对《增删卜易》《卜筮正宗》的用神、世应、旬空月破、进退神与应期章节进行
   定向二次提炼。
3. 将直接、可定位、通过治理门禁的规则追加到独立六爻知识链，并让现有报告引用
   新增古籍证据。
4. 保持八字链、六爻公开接口、装卦算法、分析状态和安全边界不变。

## 非目标

- 不把用户新提供的重复 PDF 登记为第三个六爻来源。
- 不重新处理整套 1517 页，不重跑七部古籍的全量提取。
- 不新增“用神指定”“吉凶趋向”或其他请求字段。
- 不把 `yingqi_timing` 从 `degraded` 升级为 `computed`，不输出具体日期或确定性应期。
- 不修改或覆盖现有 70 条候选、评审、晋升与证据记录。
- 不把医疗、法律、投资、寿命生死等高风险占断规则晋升为可执行结论。

## 来源身份与目录更正

### D1 单一来源身份

所有本轮候选继续使用 `liuyao_source_batch_20260714_001`，并沿用该来源已绑定的
batch file result 与冻结清单哈希。用户新文件的路径和二进制哈希不进入运行时包、
候选台账或证据台账。

新增或更新非运行时文档 `docs/classical_sources/liuyao_source_catalog.md`，记录：

- source 001 实际覆盖的七部书名；
- 各书在合集中的 PDF 起始页；
- 内容等价核验结论；
- “同内容不同封装，不新增来源”的去重裁决。

冻结的 batch_20260714 manifest 不回写、不改名；既有来源台账也不修改旧记录。

### D2 规格状态更正

更新 020/021 相关设计与执行记录中仍将《增删卜易》《卜筮正宗》写为“尚未纳入”
或“后续新增来源”的陈旧说明，改为“已包含于 source 001，本轮做定向补提炼”。
历史执行事实不删除，只追加更正说明。

## 定向页段

### D3 第一优先级：《增删卜易》（PDF 页 2-291）

首轮只处理目录直接指向核心方法的页段：

- PDF 页 27-29：用神、原神、忌神、仇神；
- PDF 页 61、65：飞伏、旬空；
- PDF 页 69-71：生克墓绝及各门类题头、应期总注；
- PDF 页 72-81：游魂归魂、月破、飞伏神、进神退神。

PDF 页 133-291 的分类占例仅用于核对上述规则的适用条件与反例；没有直接规则陈述
或页级定位的案例不晋升。

### D4 第二优先级：《卜筮正宗》（PDF 页 292-528）

首轮处理：

- PDF 页 300-310：启蒙节要、用神不上卦、用神伏藏、日辰、旬空、月破等定例；
- PDF 页 332-344：用神分类、原忌仇神、飞伏、四生、月破、旬空、进退神及流派辨析；
- PDF 页 477-526：十八问答附占验，重点核对旬空、月破、用神不现、进退神、
  生克墓绝和应验条件。

《黄金策》分类章节只在能直接补充目标规则族的限制、冲突或适用条件时引用，
不展开为新的全类别提炼任务。

## 提炼与晋升流程

### D5 先复用既有学习记录

实现阶段先搜索 `batch_20260714_learning_records.json` 与 validated outputs：

1. 以 source 001、目标 PDF 页段和 `rule_candidate` 类型筛选；
2. 对候选的原始结论、触发条件、限制与页码逐条复核；
3. 已经晋升或签名等价的内容标为重复，不创建新记录；
4. 只有现有记录无法覆盖明确的古籍规则时，才进入定向再提取。

本设计不自动授权新的远程模型调用。若现有授权不能覆盖定向再提取，或乱码文本需要
外部多模态处理，执行阶段必须停止并单独取得所有者授权。

### D6 定向再提取边界

定向再提取以“章节”为最小任务，不扩大到相邻整书。每条结果必须同时具备：

- source 001 身份；
- 单页或连续页范围 `page:N` / `page:N-M`；
- 可从页面原文直接支持的结论；
- 明确触发条件与限制；
- `ordinary` 或经收窄后可安全保留的风险等级；
- 不含绝对化、现实保证或专业建议替代措辞。

OCR 乱码导致无法确认关键术语时，必须视觉复核原页；仍不能确认则记录为证据缺口，
不得推测补字。

### D7 目标族映射

候选只能映射到以下既有规则族：

- `yingqi_timing`：应期条件、空破填实、用神旺衰、进退神等传统候选信号；
- `shi_ying_relation`：世应爻位、生克、冲合及其明确适用语境；
- `yong_shen_selection`：用神、原神、忌神、仇神与伏藏条件；
- `month_day_strength`、`void_break_state`、`moving_line_dynamics`：仅接收直接对应的
  月日、旬空月破和动变规则。

不因关键词相似把分类占断强行改入上述族。存在《增删卜易》与《卜筮正宗》观点分歧
时，两条证据分别保留并登记冲突，不裁成唯一规则。

### D8 追加式治理链

通过复核的候选进入新的追加式批次，沿用现有链条：

`learning record -> candidate -> review decision -> promotion batch -> evidence unit`

要求：

- 现有前 70 条记录的字段值、顺序和标识保持不变；序列化 diff 只允许增加
  记录分隔符与尾部新记录；
- 新候选使用连续新 ID；
- 评审理由写明原文页段、族映射依据、限制与冲突状态；
- 晋升前执行内容签名查重、页码校验、安全门禁和链完整性验证；
- 任一步失败时五个知识台账全部回滚，不留下半写入状态。

## 运行时影响

知识激活层继续按规则族读取全部已晋升证据，因此新增证据会自动出现在对应族的
`evidence_citations` 中。允许变化的只有引用数量、引用内容和证据说明。

以下行为必须保持不变：

- 所有公开函数签名与 CLI JSON 契约；
- 八个规则族的现有状态；
- `yingqi_timing.status == "degraded"`；
- 应期降级说明继续指出缺少治理化的用神指定与事项趋势输入；
- 六爻装卦、分析观察文本、边界拒绝与免责声明；
- 八字知识、校准、报告与发布审计行为。

## 错误处理

- 重复来源或重复候选：记录去重结果，不晋升，不报成功新增。
- 页码越界、来源不匹配或无法回查原文：拒绝候选。
- 族映射不明确：保留为未晋升学习记录，并记录恢复条件。
- 高风险或绝对化内容：拒绝或收窄为不可执行的文献观察。
- 台账写入后链校验失败：恢复写入前全部台账字节。
- 新远程处理缺少明确授权：停止，不发起调用。

## 验收标准

1. 来源目录文档明确 source 001 覆盖七部古籍，并记录重复封装裁决；无新增 source。
2. 目标页段全部形成“已复核、重复、拒绝或证据缺口”之一的可审计结果，不留静默遗漏。
3. 每条新增证据都能回溯到 source 001 与准确 PDF 页码，且通过查重、安全和链校验。
4. 前 70 条证据及其关联台账记录保持不变；新增记录只追加。
5. `yingqi_timing` 保持 `degraded`，公开接口和 JSON schema 不变。
6. 新增古籍引用能在现有六爻报告中确定性渲染；相同输入输出逐字节一致。
7. 六爻专项测试、知识链测试、mypy、Ruff、`git diff --check`、全项目回归与 main
   发布审计全部通过后，方可声明本轮完成。
