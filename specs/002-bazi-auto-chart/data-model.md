# Data Model: 八字自动排盘层 MVP

## AutomaticChartRequest

Represents a request to calculate a chart from a birth profile.

**Fields**:

- `calendar_type`: must be公历-compatible (`gregorian`, `solar`, `公历`)
- `birth_date`: `YYYY-MM-DD`
- `birth_time`: `HH:MM`
- `birthplace`: user-provided place text, required for report display and assumptions
- `gender`: user-provided value retained for future domain rules
- `focus_topic`: safe user focus topic

**Validation rules**:

- All fields are required for chart calculation.
- Unsupported calendar types stop calculation.
- Invalid date/time formats stop calculation.
- Red-line focus topics stop automatic report generation.

## ProviderPillar

Internal provider result for one calculated pillar.

**Fields**:

- `name`: `year`, `month`, `day`, or `hour`
- `gan_zhi`: combined stem/branch string
- `heavenly_stem`
- `earthly_branch`
- `hidden_stems`
- `ten_god`
- `element`

**Validation rules**:

- A provider result must contain exactly four pillars.
- Each pillar must have non-empty stem and branch values.
- Hidden stems may be empty only if the provider returns no data for that branch.

## CalculatedBaziChart

Project-owned chart object produced by automatic calculation.

**Fields**:

- `birth_profile`: original `BirthProfile`
- `chart_source`: `ChartSource` with automatic-calculation provenance
- `pillars`: four `Pillar` values
- `day_master`: day heavenly stem
- `five_elements_summary`: qualitative summary generated from calculated pillar elements
- `ten_gods_summary`: conservative summary generated from calculated ten-god values
- `strength_assessment`: conservative note, not a final旺衰 verdict
- `pattern_candidates`: conservative candidate list
- `useful_god_candidates`: conservative candidate list
- `luck_cycle_summary`: conservative note, not a大运 calculation

**Validation rules**:

- Must contain exactly four pillars.
- Must use `chart_source.source_type = "auto_calculated"`.
- Must use `chart_source.confidence = "medium"`.
- Must state no true solar time was applied.

## AutomaticChartSource

Provenance for an automatically calculated chart.

**Fields**:

- `source_type`: `auto_calculated`
- `source_note`: states that the engine calculated the chart and no manual review occurred
- `calendar_assumption`:公历 input and solar-term boundary handling
- `timezone_assumption`: China standard time `UTC+08:00`
- `solar_terms_assumption`: solar-term data comes from the calendar provider
- `true_solar_time_applied`: `False`
- `confidence`: `medium`

**Validation rules**:

- Must be visible in chart JSON and automatic reports.
- Must not imply manual verification.

## CalculationError

Stable user-facing error condition for invalid or unsupported calculation requests.

**Fields**:

- `category`: unsupported calendar, invalid date, invalid time, incomplete input, provider failure, or safety refusal
- `message`: short user-facing explanation
- `details`: optional list of field names or safe redirect categories

**Validation rules**:

- CLI errors must not expose tracebacks.
- Unsupported cases must not emit partial charts or formal reports.

## AutomaticReport

A Markdown report generated by first calculating a `BaziChart`.

**Relationships**:

- Uses `AutomaticChartRequest` as input.
- Produces `CalculatedBaziChart`.
- Reuses existing `Report` and Markdown renderer.

**Validation rules**:

- Must include automatic source disclosure.
- Must include existing report disclaimer and ethics reminder.
- Must be blocked if intake validation, safety review, or calculation validation fails.
