# Feature Specification: Liuyao Najia Calculation Engine V1 (六爻纳甲推算引擎)

**Feature Branch**: `020-liuyao-najia-engine`

**Created**: 2026-08-19

**Status**: Draft

**Input**: User description: "建立六爻（纳甲筮法）推算引擎：显式爻录入、时间起卦、数字起卦三种起卦方式；独立规则族空间；先复用现有提取资料、后续增补《增删卜易》《卜筮正宗》；与八字引擎同级的授权、安全、隐私、可复核与校准治理"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 显式录入六爻获得装卦与分析 (Priority: P1)

用户摇卦完毕后，把六个爻的阴阳与动静（含变爻）逐爻录入，系统返回完整装卦结果：本卦、变卦、互卦、宫属、纳甲干支、五行六亲、世应、伏神、六神、月建日辰与空亡月破日破状态，并给出带来源依据、限制与免责声明的结构化解读。

**Why this priority**: 显式爻录入是信任根——摇卦的随机性不进入引擎，一切推算都可由输入完全复现；这是全部后续能力（校准、报告、知识链）的最小闭环。

**Independent Test**: 录入一组已知六爻（含变爻），即可独立验证装卦每个字段与传统纳甲规则一致，并产出完整报告，无需任何其他故事。

**Acceptance Scenarios**:

1. **Given** 一组合法六爻（六爻阴阳、零至六个动爻）与一个公历起卦时刻，**When** 请求装卦，**Then** 返回本卦、变卦、互卦、宫属、逐爻纳甲干支、五行、六亲、世应位置、伏神、六神、月建、日辰、空亡与月破日破标记，且结果逐字段可复算。
2. **Given** 同样的输入重复请求，**Then** 输出逐字节一致（完全确定）。
3. **Given** 非法输入（爻数不为六、动爻引用不存在的爻、日期超出支持范围），**When** 请求装卦，**Then** 拒绝并给出具体原因，不产生任何部分结果。

---

### User Story 2 - 时间起卦与数字起卦 (Priority: P2)

用户可以不手动摇卦：提供一个公历时间（时间起卦）或一组数字（数字起卦），系统按确定性规则换算出六爻，再执行与故事 1 相同的装卦与分析。

**Why this priority**: 覆盖无手动摇卦场景；换算法是确定性纯函数，可完整测试与校准。

**Independent Test**: 用文献可考的时间/数字样例验证起卦换算结果，并确认其后续装卦与显式录入等价。

**Acceptance Scenarios**:

1. **Given** 支持范围内的公历时间，**When** 选择时间起卦，**Then** 按明确文档化的换算规则得到六爻并完整装卦。
2. **Given** 两个正整数输入，**When** 选择数字起卦，**Then** 按明确文档化的换算规则得到六爻并完整装卦。
3. **Given** 起卦方式未指定或输入不足，**When** 请求起卦，**Then** 拒绝并说明需要哪种输入。

---

### User Story 3 - 传统方法解读报告 (Priority: P2)

用户获得一份六爻解读报告：用神取用线索、世应关系、动爻生克、六神临持、月日旺衰、空亡月破状态、应期候选与分类事项观察；每条结论都带规则族、证据来源、强度、限制与不确定性措辞，高风险内容（生死、疾病、重大决策）降级或拒绝。

**Why this priority**: 装卦是事实，解读是价值；报告必须延续本项目的护栏传统（不作确定性预测、不作专业建议替代）。

**Independent Test**: 对固定装卦输入验证报告的族覆盖、措辞边界、证据可追溯与高风险降级行为。

**Acceptance Scenarios**:

1. **Given** 一份完整装卦，**When** 生成报告，**Then** 报告包含免责声明、每个启用规则族的结论或其降级说明、证据来源引用与限制语言。
2. **Given** 涉及寿命、死亡、医疗诊断、法律裁决等高风险主题的请求，**When** 生成报告，**Then** 系统拒绝或降级为传统信号描述并附明确边界，绝不输出精确断语。
3. **Given** 存在流派或来源分歧的规则，**When** 生成报告，**Then** 报告呈现候选与分歧而非唯一断言。

---

### User Story 4 - 六爻知识学习与传统校准 (Priority: P3)

维护者能够把六爻典籍候选（本批次已提取的学习记录、后续增补典籍）经确定性门禁晋升进独立的六爻知识链，并用合成用例校准引擎与传统方法的一致性。

**Why this priority**: 知识晋升与校准决定了解读的语料质量与可信度声明的边界；八字体系已验证同构治理可行。

**Independent Test**: 晋升记录全部可追溯（文件哈希+页码定位）；校准用例全部为合成输入、双评审、有裁决与一致性指标。

**Acceptance Scenarios**:

1. **Given** 一条带来源定位的六爻规则候选，**When** 通过门禁晋升，**Then** 生成相互链接的候选、评审决定、晋升批次与证据记录，且不修改任何既有知识记录。
2. **Given** 一组合成校准用例，**When** 执行校准，**Then** 产出与独立评审裁决的一致性指标，且任何不一致都被记录。
3. **Given** 八字既有知识与校准基线，**When** 六爻知识链变更，**Then** 八字链路与校准结果不受影响（独立族空间）。

## Functional Requirements

- **FR-1**: 系统必须接受显式六爻录入（六爻阴阳属性与零至六个动爻标记）与起卦时刻，并返回完整装卦：本卦、变卦、互卦、宫属、逐爻纳甲干支、五行、六亲、世应、伏神、六神、月建、日辰、空亡、月破与日破。
- **FR-2**: 系统必须支持时间起卦与数字起卦两种确定性换算方式，换算规则必须明确文档化；任一输入缺少或不合法时必须拒绝并说明原因。
- **FR-3**: 全部装卦与解读输出必须完全确定：相同输入产生逐字节一致的输出；引擎不模拟任何随机过程。
- **FR-4**: 解读必须按独立六爻规则族组织（如用神取用、世应关系、动爻生克、六神临持、月日旺衰、空亡月破、应期推断、分类事项），且与八字规则族空间隔离，互不影响。
- **FR-5**: 报告必须包含免责声明、来源依据、规则族、结论强度、限制与不确定性措辞；涉及寿命、死亡、医疗、法律、重大财务决策等高风险主题时必须拒绝或降级为传统信号描述并附明确边界。
- **FR-6**: 系统不得持久化任何起卦输入、卦例或生成的报告；推算与报告在同一进程内完成。
- **FR-7**: 知识晋升必须沿用候选-评审-批次-证据的链接记录与确定性门禁（定位核验、措辞门禁、去重、冲突登记），只追加、永不覆盖既有记录；八字与六爻知识链各自独立验证。
- **FR-8**: 校准必须只使用合成（非真实个人）用例，包含独立评审、裁决与一致性指标；发布状态必须绑定精确版本集合。
- **FR-9**: 起卦日期支持范围与历法换算假设必须明确文档化（与现行八字引擎的历法服务一致）。
- **FR-10**: 系统必须通过命令行与严格 JSON 入口提供推算能力，入口对输入大小与结构有明确上界。

## Success Criteria

- **SC-1**: 文献可考的装卦样例（不少于 20 个，覆盖八宫各宫、含变卦/伏神/空亡等情形）逐字段一致率 100%。
- **SC-2**: 三种起卦方式各有文档化换算规则与通过样例；相同输入重复 20 次输出逐字节一致。
- **SC-3**: 校准用例（不少于 40 条覆盖全部启用规则族）经两名独立评审与裁决后，裁决一致项的引擎符合率达到发布门阈值（沿用 019 的阈值标准），安全关键断言一致率 100%。
- **SC-4**: 报告边界测试：高风险请求拒绝或降级率 100%，绝对化断语（必定/注定等）在报告中出现率为 0。
- **SC-5**: 隐私测试：推算过程对输入与报告零持久化；合成校准语料不含任何真实个人信息。
- **SC-6**: 新增知识记录 100% 可追溯到文件哈希与页码级定位；既有八字知识链、校准基线与全部既有测试在六爻引入前后保持一致。
- **SC-7**: 完整回归套件、类型与静态检查、安装包验证全部通过后，方可在文档中声明 V1 完成。

## Key Entities

- **起卦请求**: 起卦方式（显式爻录入/时间起卦/数字起卦）、六爻明细或换算输入、起卦时刻、可选输入标识。
- **装卦结果**: 本卦、变卦、互卦、宫属、逐爻干支五行六亲、世应、伏神、六神、月建日辰、空亡月破日破标记。
- **六爻规则族**: 独立命名空间下的解读族定义（含启用状态与版本）。
- **解读报告**: 按族组织的结论、强度、证据引用、限制、分歧与免责声明。
- **知识记录**: 候选、评审决定、晋升批次、证据单元及其相互链接与来源定位。
- **校准资产**: 合成用例、断言、评审包、双评审记录、裁决、指标快照与发布决定。

## Assumptions

- V1 仅覆盖纳甲筮法；梅花易数等其他起卦断法体系不在本特性范围。
- 摇卦随机过程不属于系统：显式录入以用户提供的摇卦结果为信任根；时间与数字起卦仅为确定性换算。
- 六爻知识链在独立规则族命名空间下建设，不修改八字十条治理规则族及其证据、校准与报告启用逻辑。
- 本批次已提取的六爻学习记录（六爻古籍经典合集、学六爻这本最好）作为首批候选来源；《增删卜易》《卜筮正宗》作为后续增补批次。

## Boundaries

- 不做科学或预测性断言；所有输出定位为传统方法的文化解读与自我反思材料。
- 不处理医疗、法律、心理、投资等专业建议；相关主题拒绝或降级。
- 不提供真实个人校准数据；校准全部使用合成输入。
- 不持久化输入与报告；不引入网络服务、数据库或界面。
- 不改变八字引擎的任何现有行为、知识链与校准基线。
